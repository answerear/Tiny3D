# Tiny3D Core Doxygen API 注释

## 目标

为指定头文件中 **class / struct 的全部成员 API**（public、protected、private）
统一重写 Doxygen。语义 **必须以对应 `.cpp` 实现为准**。

## 硬性约束（必守）

1. **先读实现，再写注释**：每个待文档函数/方法，必须先打开并阅读对应
   `.cpp` 中的定义（或头文件内完整内联实现），依据控制流、返回值、
   空指针/错误路径、生命周期与副作用来写。
2. **禁止臆造**：
   - 禁止只根据函数名、参数名「望文生义」写行为说明；
   - 禁止编造代码中不存在的约定、错误码、线程安全或副作用；
   - 实现看不清时：只写有把握的 `\brief`，并在回复中列出「待人工确认」项，
     不要用 `\remarks` 填补猜测。
3. **统一重写**：目标范围内已有 Doxygen / `///` 一律按本 skill 风格与实现语义重写；
   不要「保留旧注释只补洞」（除非用户当次明确说「只补缺失」）。
4. **只改注释**：不改签名、成员顺序、逻辑或无关格式化。

## 输入

用户指定其一即可：
- 库：`Core`（默认扫描 `source/Core/Include`）
- 目录：如 `source/Core/Include/Kernel`
- 单个/多个头文件

未指定范围时先确认再动手。大目录先列文件清单，分批（按子目录）推进并汇报进度。

## 工作流

```
Doxygen Progress:
- [ ] 1. 枚举目标 .h
- [ ] 2. 配对并打开 .cpp
- [ ] 3. 列出全部成员 API（含 private）
- [ ] 4. 逐 API：读实现 → 写/重写注释
- [ ] 5. 自检风格与实现一致性
```

### 1. 枚举头文件

扫描目标下 `*.h`。默认跳过纯聚合转发头（如 `Tiny3D.h`），除非用户点名。

### 2. 配对实现（写注释前必须完成）

| Header | Source |
|--------|--------|
| `source/Core/Include/<Mod>/T3DXxx.h` | `source/Core/Source/<Mod>/T3DXxx.cpp` |

- 同名 `.cpp` 优先；找不到则在 Core 内搜索该符号定义。
- **模板 / 纯头内联**：以声明处函数体为准，仍须通读实现，不得凭名字写。
- **纯虚接口**：可读派生类覆盖或调用方，仍不得臆造；信息不足则 brief 从简并标记待确认。
- 一个 `.h` 对应多个 `.cpp` 时，按实际定义所在文件阅读。

### 3. 覆盖范围

- 默认：**所有**访问级别（`public` / `protected` / `private`）的方法、静态方法、
  工厂函数；以及类/枚举自身的类级注释。
- 一并处理：嵌套类型、枚举（若在类内或文件内作为 API 表面）。
- 可跳过：纯 `friend` 声明、无独立语义的宏展开行、`= delete` 且无额外约定时可用极简 brief。
- 简单 getter/setter：若实现确无副作用，可用 `///`；一旦有校验、缓存、懒加载等，必须块注释并写清。

### 4. 逐 API 写注释

对每个成员严格按序：
1. 定位并阅读 `.cpp`（或内联体）；
2. 归纳：输入约束、输出/返回、失败与空指针、调用时机；
3. 用下方模板写中文注释；
4. 用新块替换该声明上方的旧 Doxygen/`///`（统一重写）。

### 5. 编辑与批量

- 缩进与周围 `/**` 块一致。
- 大范围按子目录分批提交进度；每批结束后简要列出已处理文件。

## 注释模板（对齐仓库）

### 类 / 枚举

```cpp
/**
 * \brief <一句话职责——来自职责与实现，非类名翻译>
 * \remarks <可选：仅当实现或引擎约定中有额外信息>
 */
```

### 成员 / 静态方法

```cpp
/**
 * \brief <做什么——来自实现行为>
 * \param [in] name : <含义；可为 nullptr / 默认值时据实现写明>
 * \param [out] out : <输出含义>
 * \return <据实现写成功/失败/空指针等>
 * \remarks <可选>
 * \note <可选；短注意点>
 */
```

### 模板参数

```cpp
 * \tparam [in] T : <约束；须能从实现或类型用法证实>
```

### 简单且无独立 param/return 价值时

```cpp
/// <一句话，仍须与实现一致>
```

## 风格细则

1. **中文**；专有名词可保留英文（GameObject、Bound、NDC、UUID）。
2. 命令用 `\`（`\brief` 等），不用 `@`。
3. `\param` 方向：`[in]` / `[out]` / `[in,out]`；格式：`\param [in] go : 说明`。
4. `TResult`：优先「调用成功返回 T3D_OK」，失败含义仅在实现可判断时写。
5. 指针 / `SmartPtr`：据实现写明何时返回或接受 `nullptr`。
6. `override`：写本类实现语义，不空洞重复基类。
7. 不添加 `\file` / `\author` / `\date`，除非用户要求。
8. `\remarks` / `\note` 仅在有额外、可证实信息时使用。

## 质量检查

- [ ] 每个重写的 API 都对照过对应实现（或内联体）
- [ ] 无「仅凭函数名」生成的行为描述
- [ ] 含 `\brief`；有参数则有 `\param`；非 void 有 `\return`（构造/析构按仓库习惯可极简）
- [ ] public/protected/private 均已覆盖（用户未缩小范围时）
- [ ] 旧注释已替换，风格统一
- [ ] 未改动非注释代码

## 用户交互

- 用户说「只补缺失」时，覆盖本 skill 默认的「统一重写」。
- 用户缩小访问级别时，按其指定范围。
- 实现缺失或行为不清：brief 从简 + 回复中列出待确认列表。
