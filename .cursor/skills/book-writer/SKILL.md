# 《一起动手实现3D渲染引擎》写作规范

书稿：`doc/一起动手实现3D渲染引擎.md`。插图：`doc/images/`。PDF 由 md 导出，不手改。

## 全书结构

全书分六个部分，每部分以 `# <center>第X部分　XX篇</center>` 加分页符开头：

- 第一部分 工程篇：第一~三章（整体设计、开发环境、第一个程序 HelloApp）
- 第二部分 基础系统篇：第四~十一章（平台层、线程任务与时间、日志、对象系统与内存管理、反射与序列化、事件、插件、档案与资源管理）
- 第三部分 数学篇：第十二~十八章（坐标系、向量、矩阵、欧拉角与四元数、几何图元、几何检测、数学库实现）
- 第四部分 渲染篇：第十九~二十六章（渲染流水线、RHI 与渲染线程、渲染资源与渲染状态、渲染管线、材质与着色器、纹理与图像、光照与阴影、渲染后端实现差异）
- 第五部分 场景与内容篇：第二十七~三十章（GameObject 与 Component、场景与 Prefab、模型和骨骼动画、输入与 UI）
- 第六部分 工具与编辑器篇：第三十一~三十三章（资产工具链、Meta 资产系统、编辑器）
- 后记——优化与展望（含规划中的功能：字体、地形、粒子）；附录

章标题分组前缀：基础系统—— / 3D数学—— / 渲染系统—— / 场景与内容—— / 工具与编辑器——。改版方案见 `doc/todo/Book-Revision-Plan-todo.md`。

新增章节按这个分组插入到合适位置，中文章序号与后续章节同步顺延；章内小节号、图号、公式号及正文引用一并重编。

## 章节模板

```markdown
# <center>九、基础系统——事件系统</center>

本篇概要

- 要点一
- 要点二


## <center>9.1 小节标题</center>

　　正文……

### 9.1.1 三级标题

　　正文……

<div style="page-break-after:always;"></div>
```

- 一级标题：`# <center>中文序号、分组——主题</center>`
- 二级标题：`## <center>章.节 标题</center>`；三级标题：`### 章.节.小节 标题`，不加 center
- 一级标题后紧跟「本篇概要」与要点列表
- 每章结尾放 `<div style="page-break-after:always;"></div>`
- 编号必须连续、与所在章一致；`<center>` 标签必须闭合

## 正文风格

- 段首用两个全角空格 `　　` 缩进；列表、代码说明行不缩进
- 口吻：第一人称「我们」，带读者「一起动手」，口语化但讲清原理，如「接下来我们看看……」「各位看官请参阅源码」
- 讲解顺序：先说为什么要有这个模块 / 要解决什么问题 → 设计（类图、设计模式）→ 关键代码 → 平台差异或注意事项 → 小结
- 数学章节：先给定义与运算法则，再讲几何意义，公式用 LaTeX `$...$` / `$$...$$`
- 讲接口时用加粗单独一行写出签名，例如 `　　**void print(const char *pText, ...)**`，下一段解释作用

## 代码

- 代码块语言标记用 ```` ```c++ ````
- 片段取自当前源码，可删减无关成员并以 `// ...` 标明；保留源码里的 Doxygen 注释有助于讲解时可保留
- 片段之后列源码路径：

```markdown
详细的实现各位看官请参阅源码：

- source/Platform/Include/T3DSingleton.h
```

- 路径用仓库相对路径（以 `source/` 开头），写之前确认文件存在。早期章节里的 `Source/...` 旧写法，在修订到该章时一并改为现路径

## 与代码的关系

- 书讲已实现的代码；设计稿只作背景。未实现部分写「后续章节再展开」
- 讲渲染、平台等跨后端 / 跨平台内容时，先讲抽象接口，再挑一个代表性实现细讲，其余列出类名请读者参阅源码
- 有对应 Sample（`source/Samples/XxxApp`）时，在章末引导读者运行该示例
